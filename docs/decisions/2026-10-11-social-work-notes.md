# Social workers can document their own visits (owner, 2026-10-11)

Owner asked whether the app works for LMSWs and LCSWs. It didn't: every note template was primary care or psychiatry, the visit timer refused them, screenings had nowhere to go, and several buttons they could see always errored when clicked.

- **Three new visit types, with a new Social Work service:** Psychosocial Assessment (`sw_psychosocial`; LMSW, LCSW or provider), Therapy Session (`sw_therapy`, under Behavioral Health; LCSW, or a provider with the behavioral health specialty), and Social Work Follow-up / Care Coordination (`sw_follow_up`; LMSW, LCSW or provider). Each can be in person, video or phone. **This changes the 2026-10-02 rule "phone is offered on no visit type other than the phone call".** That rule was about medical visits written up as calls. None of these bill E/M, so they declare phone explicitly, and the test now checks only medical types.
- **`noteShape: 'sections'`: the note is only its template sections.** No vitals, no physical exam, no home-visit nursing blocks, and it is never an H&P. The server enforces this in `sanitizeNote` whatever the page sends (`isSectionsOnly`), so a social work note never demands a blood pressure and never marks the initial visit as done. The phone call goes through the same path now (its template is the one Call note box).
- **Minutes are required on every one:** `sessionTime` on therapy (psychotherapy is billed by time), `contactTime` on the other two. The safety plan becomes required once risk is positive, as on the psych types.
- **The structured risk assessment is required to sign therapy (Behavioral Health service) and the psychosocial assessment (`riskAssessmentRequired: true`).** Not required on the follow-up. Read through `appointmentTypes.requiresRiskAssessment`.
- **Code family:** a type can declare its own (`codeFamily`). Therapy and the psychosocial assessment bill `behavioral_health` and the follow-up bills `care_management`, never E/M, whatever the modality.
- **Who may write which note: `canDocumentType(type, clinicalRole)`.** An LMSW writes psychosocial and follow-up notes, an LCSW all three, an RN no psychotherapy note, a provider anything. Served per type as `canDocument` so the picker only offers those. Enforced by `noteTypeRefusal` on note create and on any note save that sets or changes the type (editing text on someone else's draft is not refused over its type). A social worker must choose a type (`VISIT_TYPE_REQUIRED`). **Not enforced for providers by specialty:** no user record holds a specialty, so the psych half of `canBookType` still can't be asked at note time. Booking carries no visit type at all, so there's nothing to check there.
- **Visit times:** `POST /api/clinical/visits/:eid/timing` is gated on writing any clinical note (`requireNoteWriter`), not the nursing note alone.
- **Buttons that always refused are hidden by capability:** med rec save (`medRec`); the "add to problem list" box (`problemListWrite`); mark faxed / scheduled / attach result (`orderStatusAdvance`); the care-plan second signature (a new served `canCoSignCarePlan`, provider or LCSW); and the Orders form for a role whose standing-order limit is screening only.
- **A real gap closed on the way:** the coding route wrote "add to problem list" codes to OpenEMR for any clinical writer, with no check for `problemListWrite`. It now skips them with a warning.
- **Screenings (`screenings.js`, new collection `clinical_screenings`, PHI, registered):** PHQ-2, PHQ-9, GAD-7 and a social needs screen, recorded on the encounter by any role with `screeningInstrument`. It records the total score and what it means, not the questions (the instruments are OpenEMR's templates, owner 2026-09-23). Naming a standing order runs the same authorization an order gets, as a `screening`, and writes a `standing_order_executions` row. **This is how the deferred "screening protocol can't be executed" defect is closed.** A screening is its own record, not an order, and `screening` was still not added to `ORDER_TYPES`. A recorded screening counts as the note's screening section and goes into the OpenEMR note under SCREENINGS RECORDED. The audit records the instrument and whether it was positive, never the score.
- **PHQ-9 item 9 is required, and any answer above 0 blocks signing until the risk assessment is recorded, on any visit type** (`SIGN_SCREENING_NEEDS_RISK`).
