# Care coordinators write care plans; a clinician's co-signature makes them active (owner request, 2026-10-14)

Owner ask: "care coordinators can also author and update a care plan and require a clinician's co-signature for it to be active."

- **This reverses one line of `2026-10-14-care-coordinator-role.md`**, which said a coordinator never authors a care plan. Everything else about the coordinator stays: no signing notes, prescribing, ordering, coding, med rec, problem list or result sign-off.
- **What a coordinator can do now:** write a new version of any client's care plan (home care or clinical) and update goal status. `coordinator` holds `carePlanAuthor`; the care-plan save route and the goal-status route moved from `requireClinicalWrite` to `requireClinicalDocumenter` (both still also need `CARE_PLAN_AUTHOR`). The co-sign route stays on `requireClinicalWrite` + `CARE_PLAN_SIGN`, so a coordinator never co-signs.
- **A coordinator's signature is always the authoring one.** `evaluateCarePlanSignature` returns pending on every service line; the plan shows "Awaiting clinician co-signature" and its PDF carries the pending banner until someone co-signs.
- **Who can co-sign is decided by the client's service line, in one place (`clinicalRoles.canCompleteCarePlan`):** someone whose own signature would complete a plan on that line. Home care: an RN, LCSW or provider (and admin). Clinical (IHPC/BOTH): an LCSW or provider. The co-sign route, the care plan screen (`canCoSign` on `GET …/care-plan`) and the clinical inbox all ask this, so the screen never offers a button the server refuses. This also corrects the inbox and screen for LMSW-authored home care plans, which an RN could already co-sign at the route but was never shown.
- **Status updates by a coordinator do not need a co-signature.** They never create a version (see `2026-10-14-care-plan-format.md`).
- **Wording:** "provider" became "clinician" where an RN can co-sign: the chip, the inbox row, the button ("Co-sign Plan") and the PDF ("Author signature", "Clinician co-signature", "PENDING CLINICIAN CO-SIGNATURE").
- **Not changed:** a pending plan is still visible to the client and caregivers and can be co-signed by the client in the portal, as with RN- and LMSW-authored plans today; "active" is marked on the plan and its PDF, not enforced by hiding it.
- **Verified:** coordinator tests repointed (the old "never authors" assertion now asserts the new rule), 3 new tests; 6 of 7 deliberate breaks caught, the seventh a recorded no-op (the `CARE_PLAN_SIGN` check inside `canCompleteCarePlan` is belt-and-braces). Full suite 2459 pass, 0 fail. `scripts/verify_care_plan_format.js` 34/34 through the real HTTP routes, including coordinator writes → RN activates a home care plan, and an RN refused on a clinical patient's.
