# Password reset reaches the right person; a "password changed" notice

Owner, 2026-10-28: asked whether patients are told when a password is reset, then chose to fix two gaps: a POA-held patient's reset, and a confirmation when someone changes their own password.

- **A placeholder login can no longer be reset.** A patient whose POA signs in with their own account has a placeholder email (`@placeholder.local`) and nobody signs in with it. A reset emailed the link to that address, so it went nowhere, while the screen said a link had been emailed. **The owner asked for the reset to go to the POA. It was built as a refusal instead**, because emailing the patient's password to the POA would put the POA back to signing in AS the patient, which the POA cutover (2026-10-20) ended: every signature and message would again carry the patient's name. The refusal (409 `RESET_PLACEHOLDER_LOGIN`) names the POA(s) on file and says to reset their own account; with no POA on file it says to add a real email first. Only POAs are named, never other family.
- **All three reset paths check it before the password changes:** the Edit User form, the single reset route, and the bulk reset (which skips the account with a reason). `placeholderResetRefusal` in `server.js` is the one rule.
- **Changing your own password sends "Your password was changed"**, with the date and time in Eastern and the office phone to call if it was not them. It is a security notice, so it is sent whatever the person's email preferences; it is never sent to a placeholder address, and it carries **no link**, so a forwarded copy gives nobody a way in. Sent after the new password is saved, non-blocking.
- **Not changed:** a "Forgot password" request still emails nobody; it waits in Inbox → Password Resets (the owner did not pick that fix).
- **Verified:** `test/password_reset_notices.test.js` (6 tests, the helpers lifted out of `server.js` and run), 5 of 5 mutations caught; one existing guard in `test/user_edit_password.test.js` repointed to allow the refusal and nothing else between the reset flag and the hash. Full suite 2672, 0 failing.
