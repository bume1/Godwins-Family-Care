# Managers and care coordinators run private home care (owner, 2026-11-03)

Brief: `GFC_PHC_Access_ClaudeCode_Prompt.md`. Managers and coordinators get the day-to-day work. The Super Admin keeps the money files, approves time and pay changes, and manages staff and clinical accounts.

- **The live defect (A1).** `isAvailabilityRecorder` tested `role === caseManager`. A coordinator is stored as `role: 'user'` with the manager flag, so every coordinator was refused, and LMSWs (who are the caseManager role) had a permission nobody meant them to have. It now reads the account type through `accountTypes.isHomeCareOffice` (admin, manager, coordinator). **LMSWs lose it, on purpose.** The test fixture had the coordinator as `caseManager`, which is why the bug never showed; it is stored the real way now.
- **Client location (A2)** is open to managers and coordinators. It still writes only the location fields.
- **Payroll and billing (A3): view, not export.** One row builder each (`buildPayrollRows`, `buildBillingRows`) feeds both the CSV (Super Admin) and the new JSON views (`GET /api/scheduling/payroll`, `/billing`, schedule-manager gate). The scheduling page shows the views as read-only tables with no download control. Each view is audited (`payroll_viewed`, `billing_viewed`). **Pay rates are shown** (assumed decision 5).
- **Manual hours and direct edits stay Super Admin (A4).**
- **Time adjustment requests (B).** `time_log_adjustment_requests` (PHI, registered). A manager or coordinator raises one, with a reason required and one pending per log (409 names the open one). Only the Super Admin decides. **Approval goes through `applyTimeLogEdit`, the same writer the admin's PUT uses**, so one code path writes time. A log changed since the request was raised is refused (`ADJUSTMENT_STALE`). The log keeps `original_clock_in/out` and `original_total_minutes` (the first originals, kept through later adjustments) and gains `adjusted`, `adjustment_request_id`, `adjusted_by_id` (requester), `approved_by_id` (admin), `adjusted_at`, `adjustment_reason`. The admin is notified when a request is raised, and the requester when it is decided.
- **Exports (C).** Payroll and billing carry `Adjusted` early (fourth or fifth column), then Original Hours, Adjusted By, Approved By, Adjusted At and Adjustment Reason after the hours. **The caregiver stays the subject of the row**; an adjustment never re-attributes it.
- **Caregiver management (D).** Document list, file, kinds and review, competencies (caregiver accounts only), and broadcasts are open to the office. `requireCaregiverOrAdmin` is renamed `requireCaregiverOrOffice`. **Deletion stays Super Admin.** Office document reads and lists are audited with role and route. **Also widened, not in the brief's table:** `POST /api/caregiver/documents`. That route shares the renamed guard, and the office now files a document for a named caregiver, as an admin does. Left alone it would have filed a manager's upload under the manager.
- **User administration (E).** `accountTypes.checkUserWrite` is the one ceiling. A manager or coordinator may create and edit caregiver, client and family accounts only. Refused: any staff type, changing a record into one, editing a staff record, editing their own record (`USER_SELF_EDIT_FORBIDDEN`), and setting any access field (`isManager`, `clinicalRole`, `hasClinicalAccess`, `managerClinicalAccess`) or credential (NPI, DEA, prescriber credential, Medicare enrollment, OpenEMR id). Blank values the form always sends are dropped so they cannot clear anything. Refusals say "A Super Admin manages staff and clinical accounts…". `POST /api/users` and `PUT /api/users/:userId` run `guardUserWrite`. MFA reset, session revoke, EMR disconnect and delete stay `requireAdmin`. A build test fails if a `/api/users` write route carries neither guard.
- **Money is request-and-approve (F).** `userFinancialFields.js` lists the fields found in the code: `payRate`, `clientPayRates`, `rateAgreement`, `billingSettings`. There is no overtime, mileage, reimbursement, bonus or stipend field today. A manager's edit saves everything else, holds the money fields, files a `user_financial_change_requests` row for each one that would actually change, and says which were held. One pending request per user per field. Only the Super Admin decides. Approval applies through the admin's own normalizers and uses `commitRate` for a client rate, so the re-signature flag still fires. A stale request is refused.
- **The user form** is served only the account types the viewer may pick (`GET /api/admin/clinical-roles` now admits the office and filters). It shows a pay-change queue (Super Admin approves) and any pending request on the record.
- **Fixed on the way:** the scheduling page's Correct Times box was filled with the raw UTC instant (`iso.slice(0,16)`), so a 9am visit showed 13:00, and saving it unchanged moved the visit four hours. It reads and writes Eastern now through `gfc-time`. The caregiver documents list also showed a blank label (it read `d.label`; the row carries `kindLabel`).
- **Verified:** `test/phc_access.test.js` (25 tests, scheduling and caregiver routers mounted and called over HTTP), 12 of 12 mutations caught (one survived first, the list audit; a test was added). `scripts/verify_phc_access.js` passes 43/43 through the real server. Ten existing tests were repointed rather than deleted. Full suite 2745, 0 failing. All three edited pages compile. **Not rendered in a browser.**

The server side is done; the screen needs a home. (2) The competency editor also sits in the Admin Hub user form, so it has the same gap. (3) Pay rates appear in the managers' payroll view (assumed decision 5).
