# Feature branches stop editing CLAUDE.md; the app stops rewriting changelog.md

Owner, 2026-09-30: "what do we need to do to avoid this constant clash of claude.md and the change log?"

- **Why it kept happening.** Every branch wrote into the same lines of `CLAUDE.md` (the "Last updated" line, "Current session focus", the status table, the top of "Recent decisions") and of `docs/GFC_SESSION_PLAN.md`. Each merge left every other open PR with a conflict. PRs #151, #152 and #153 each needed a manual merge on 2026-09-29/30 for docs alone; no code clashed.
- **The rule now.** A feature branch writes its notes as a new file in `docs/decisions/`. Shared lines change only in a docs-only PR after merges. Written into "Running instruction" at the bottom of `CLAUDE.md`.
- **`public/changelog.md` is no longer rewritten at boot.** `autoUpdateChangelog` rewrote it on every start, so every branch carried a change to it. Nothing serves the file: the `/changelog` page reads the database entry, which still updates at boot. Regenerate the file on purpose with `node changelog-generator.js`. Guarded by a test in `test/changelog_idempotent.test.js`, which fails if the boot write comes back (checked by putting it back).
- **A flaky test fixed on the way.** `test/changelog_idempotent.test.js` failed about 1 run in 6 on main with "Unable to deserialize cloned data": the writer's console line, printed inside a test file, corrupted Node's test-runner stream. The test now holds console output back while the writer runs. 15 of 15 runs passed after the fix.
